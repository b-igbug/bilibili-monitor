# B站 UP主 动态监控 → 飞书推送（云端自动运行）

## 这个方案解决什么
你想在 **B站 UP主 发新动态时收到飞书通知**，但电脑可能关机。所以把监控放到 **GitHub Actions**（GitHub 免费提供的云端定时任务）上跑，**你的电脑关机也不受影响**。

监控的 UP 主：
| UP主 | UID |
| --- | --- |
| 我走路带风风风 | 3706962053172003 |
| 站在黎明 | 3747571396775777 |

推送目标：你的飞书群机器人（webhook 已内置在脚本里）。

## 一、文件清单
项目里有 3 个文件，全部要上传到 GitHub 仓库：

```
bilibili_monitor/
├── monitor.py              ← 核心脚本（抓动态+比对+推飞书）
├── .github/
│   └── workflows/
│       └── monitor.yml     ← 定时任务配置（每5分钟跑一次）
└── state.json              ← 状态文件（记录每条已推送的动态ID，自动更新）
```

## 二、部署步骤（照着做即可）

### 第 1 步：注册 GitHub 账号（如果没有）
打开 https://github.com ，点 **Sign up** 注册（免费）。注册好并登录。

### 第 2 步：新建一个仓库
1. 登录后点右上角 **“+”** → **New repository**
2. Repository name 填：`bilibili-monitor`
3. 下面选 **Public**（公开）或 **Private**（私有）都可以，推荐 Private
4. 直接点 **Create repository**

### 第 3 步：上传文件到仓库
在你的仓库主页，点 **Add file** → **Upload files**：

把下面这些**拖进上传框**即可（注意目录结构）：
- 把 `bilibili_monitor` 文件夹整个拖进去，或分别拖 `monitor.py`、`state.json`、以及 `.github/workflows/monitor.yml`

> 关键：`.github/workflows/monitor.yml` 必须在 `.github/workflows/` 这个目录里，不能放错位置，否则定时任务不会生效。

上传后点 **Commit changes** 提交。

### 第 4 步：手动跑一次（建立基线，不发通知）
1. 仓库主页点 **Actions** 标签
2. 左侧看到 `bilibili-monitor` 工作流，点它
3. 点右上 **Run workflow** 按钮 → 再点一次确认
4. 等待几十秒，点进刚运行的那次，看日志是否出现：
   - `首次建立基线` 或 `无新动态` —— 说明成功，开始进入正轨
   - （如果出现 `抓取失败或暂无动态，跳过`，请看下面的“常见问题”）

### 第 5 步：之后就不用管了
系统会**每 5 分钟自动跑一次**。以后两位 UP 主一但发了新动态，飞书就会收到通知，格式如下：

```
【我走路带风风风】发布了新动态
时间：2026-11-09 13:05
内容：……
链接：https://t.bilibili.com/xxxx
```

## 三、常见问题（Troubleshooting）

**Q1：日志一直显示“抓取失败或暂无动态，跳过”**
这通常是 B站 对某些 IP（尤其机房 IP）做了风控限流。偶尔出现没事，下一轮会自动重试；如果**持续**出现：
- 可以把 `monitor.yml` 里的定时从 `*/5` 改大一点，比如每小时一次（`0 * * * *`），降低频率减少风控
- 或在配置区增加你的 B站登录 cookie（需要把浏览器里登录 B站后的 `SESSDATA` 等 cookie 填进脚本的请求头），命中率最高
- 或改用你自己的常开设备（见下面第四部分）

**Q2：UP主发了动态但没收到通知？**
先看 Actions 最新一次运行的日志有没有 `抓取失败`；如果有，说明当轮被风控，下一轮一般会补上（只延迟、不漏报，因为没抓到就不会误报）。

**Q3：首次跑会不会把旧动态都推一遍？**
不会。首次运行只记录当前最新动态做“基线”，从第二次起，只有比基线更新的动态才会推送。

## 四、其它常开方式（如果你有这些设备，更省心）
脚本（`monitor.py`）在任何能联网、常开的设备上都能跑，效果一样：
- **NAS / 家里的小主机 / 树莓派**：装 Python，用系统的定时任务每几分钟跑 `python monitor.py` 即可
- **轻量云服务器**（如腾讯云/阿里云最低配，几块钱一个月）：定时跑 `python monitor.py`
- 这些设备上跑，不依赖 GitHub，也不占 GitHub 免费额度

## 五、改监控对象 / 换飞书机器人
改 `monitor.py` 顶部“配置区”即可：
- `UP_LIST`：加监控的 UP，照着格式加一行（`"uid": "…", "name": "…"`）
- `FEISHU_WEBHOOK`：换飞书机器人就改这行地址
